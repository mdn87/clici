# clici v0.1 Implementation-Completion and Windows Proof Plan

- **Status:** Execution in progress — automated baseline passed; interactive Windows matrix pending
- **Specification:** [Introductory Slice and Windows Platform Proof of Concept](introductory-slice-spec.md)
- **Implementation baseline:** `3fba8badb2661a3b5c1ebafa64a1fec77159da13`
- **Target:** Evidence-backed local Windows POC
- **Scope:** Complete proof and resolve findings; do not redesign already aligned behavior

## 1. Objective

Turn the implementation-aligned clici scaffold into an evidence-backed Windows
platform proof.

The code through the baseline commit already implements the normative v0.1
behavior. This plan therefore focuses on:

1. preserving a reproducible automated baseline;
2. proving tray, clipboard, targeting, and lifecycle behavior in real Windows
   applications;
3. exercising clipboard history, remote clipboard, contention, focus timing,
   and multiple-instance conditions;
4. making explicit product decisions where the proof exposes tradeoffs; and
5. publishing a concise proof report and release recommendation.

Implementation changes are contingent on observed failures. Work that already
passes the specification shall not be rewritten merely to satisfy the plan.

## 2. Completion criteria

The plan is complete when:

- AC-001 through AC-020 pass on the final commit;
- POC-01 through POC-07 and POC-09 have recorded evidence;
- all 19 manual proof-matrix steps have a result;
- no test demonstrates repeated margin removal when the clipboard input is
  byte-for-byte identical to clici's current last-written output;
- a second same-session instance cannot create another listener;
- malformed configuration is not overwritten after fallback;
- process names observed in real terminals are recorded;
- the foreground-versus-clipboard-owner limitation has a decision;
- Win+V, clipboard-manager, and RDP behavior is documented;
- POC-08 has an explicit preserve-now or defer decision;
- the specification and README reflect the observed support boundary; and
- `main` builds in Release with no warnings and has a clean test run.

Broader distribution remains out of scope unless the proof report recommends it
and the non-text clipboard-format decision is resolved.

## 3. Working rules

- Use only synthetic, non-sensitive proof fixtures.
- Never record arbitrary clipboard contents or copied fragments.
- Identify fixtures by ID in logs and reports.
- Keep diagnostic logging off except during a named proof run.
- Store raw machine-specific artifacts under `artifacts/v0.1-proof/`; this path
  is already ignored.
- Commit only the summarized proof report and deliberate product changes.
- Record failures before changing code.
- Keep each corrective implementation batch tied to a failed proof case.
- Rerun the failed case, related automated tests, and the final full suite after
  every corrective batch.
- Do not add a keyboard hook, installer, settings GUI, server, or network
  dependency during this plan.

## 5. Proof fixtures

Use a fixed synthetic fixture set so no personal clipboard data enters evidence.

| ID | Purpose | Expected default behavior |
|---|---|---|
| FX-01 | Standard two-space common margin | Normalize once |
| FX-02 | Mixed two- and four-space indentation | Remove two; preserve nesting |
| FX-03 | Six-space indentation on every line | Normalize once; suppress byte-identical last-written output |
| FX-04 | Too many column-zero lines | Leave unchanged |
| FX-05 | Too few margin-prefixed lines | Leave unchanged |
| FX-06 | Tabs and one-space prefixes | Do not treat them as the margin |
| FX-07 | Blank lines and trailing newline | Ignore blanks in ratios; preserve terminator |
| FX-08 | Unicode text | Preserve content |
| FX-09 | Single-line text | Leave unchanged |
| FX-10 | Text plus rich clipboard formats | Record text and format behavior |

The canonical FX-01 through FX-09 definitions live in
`tools/proof/fixtures.json` and are validated against `MarginNormalizer` by the
Core test suite. FX-10 remains manually sourced because a plain-text fixture
cannot prove rich clipboard formats. Do not add a general-purpose clipboard
utility to the product.

## 6. Execution phases

### Phase 0 — Baseline and environment record

**Goal:** Establish a reproducible starting point before interactive testing.

Tasks:

1. Confirm `main` is clean and matches `origin/main`.
2. Record the baseline commit, Windows version, installed .NET SDK, architecture,
   and active user session type.
3. Restore, format-check, build Release, and run all tests.
4. Confirm `clici.Core` has no packages or project references.
5. Run the named-mutex acquisition/reacquisition smoke test.
6. Run the native clipboard-listener register/unregister smoke test.
7. Confirm no diagnostics or generated configuration are inside the repository.

Commands:

```powershell
git status --short --branch
dotnet --info
dotnet restore clici.sln
dotnet format clici.sln --verify-no-changes --no-restore
dotnet build clici.sln --configuration Release --no-restore
dotnet test clici.sln --configuration Release --no-build
dotnet list src/clici.Core/clici.Core.csproj package
dotnet list src/clici.Core/clici.Core.csproj reference
```

The first Phase 0 `dotnet format --verify-no-changes` run is advisory. Record
its result, but pre-existing style drift on the baseline commit is not a proof
failure and shall not trigger a baseline reformat. Release build and test
results remain gating.

Run the named-mutex and listener lifecycle smoke with the checked-in
`tools/proof/Invoke-CliciLifecycleProof.ps1` helper after the Release build.
The helper enumerates top-level windows whose caption is exactly
`clici clipboard listener`, associates each one with its owning process ID, and
uses bounded polling rather than fixed sleeps. It shall:

1. fail before launching if a clici process already exists;
2. start the primary and require exactly one listener owned by its PID;
3. start a secondary and require it to exit within five seconds with code zero;
4. require one clici process and the same single listener after the secondary;
5. prompt the operator to choose **Exit** from the tray menu;
6. require the primary to exit and the listener count to reach zero;
7. start a new instance and require exactly one listener owned by its PID;
8. prompt for tray **Exit** again and require zero processes and listeners.

This is a PowerShell-assisted manual smoke, not an automated test. Manual tray
Exit is intentional because terminating the process would not exercise
`ExitThreadCore`. Clipboard mutation is excluded from Phase 0; the native
notification path is exercised with the canonical synthetic fixtures in
Phases 2 and 4.

Exit criteria:

- Release build has zero warnings and errors.
- AC-001 through AC-020 pass.
- The PowerShell-assisted mutex/listener lifecycle smoke passes.
- `environment.md` and the initial ledger exist locally.

### Phase 1 — Tray, configuration, and lifecycle proof

**Goal:** Prove POC-01, POC-06, and POC-09 before changing clipboard content.

Tasks:

1. Launch clici and confirm one tray icon and no main window.
2. Verify Enabled, Pause/Resume, Open configuration file, Open configuration
   folder, and Exit menu items.
3. Confirm first-run configuration location and default ratio property names.
4. Toggle Enabled and confirm persistence after a clean restart.
5. Pause and resume without changing the persisted Enabled value.
6. Introduce a synthetic malformed configuration, restart, toggle Enabled, and
   confirm the malformed file remains byte-for-byte unchanged.
7. Restore a valid synthetic configuration.
8. Start a second clici process and confirm it exits before creating a tray icon
   or clipboard listener.
9. Exit the primary instance and confirm the process terminates.
10. Relaunch to prove mutex release and listener re-registration.

Evidence:

- Tray screenshots without clipboard content.
- Configuration file hashes before and after the malformed-file toggle.
- Process list showing only one persistent clici process.
- Lifecycle timestamps and exception types, if any.

Exit criteria:

- POC-01, POC-06, and POC-09 pass.
- CONF-005/006 and LIFE-001 through LIFE-005 have observed evidence.

### Phase 2 — Core end-to-end terminal matrix

**Goal:** Prove ordinary normalization and paste behavior in intended hosts.

Minimum source matrix:

| Source | Required fixtures | Primary destination |
|---|---|---|
| Windows Terminal + `pwsh` | FX-01 through FX-09 | Notepad |
| Windows PowerShell | FX-01, FX-02, FX-03, FX-04 | Notepad |
| `cmd` | FX-01, FX-02, FX-03, FX-04 | Notepad |
| Codex in its actual terminal host | FX-01, FX-02, FX-03, FX-04 | Notepad |
| Claude Code in its actual terminal host | FX-01, FX-02, FX-03, FX-04 | Notepad |

Destination coverage:

- Repeat FX-01 through FX-03 from one representative approved source into
  Notepad, Windows Terminal, and the user's normal code editor.

For every source:

1. Record the visible application and actual foreground process name.
2. Copy an eligible fixture and confirm exactly one normalization.
3. Put clici's normalized FX-03 output back on the clipboard byte-for-byte and
   confirm last-written suppression prevents another margin removal. Then
   re-copy the visually identical output through the terminal and compare its
   bytes before judging the result: a byte-different terminal re-copy may be
   normalized again and is a documented limitation, not a proof failure.
4. Copy ineligible fixtures and confirm the clipboard string remains unchanged.
5. Confirm nested indentation, Unicode, and source line endings where observable.
6. Repeat with clici paused and disabled.

Exit criteria:

- POC-02, POC-03, and POC-04 pass for the supported source matrix.
- Default allowed process names are confirmed or corrected from evidence.
- Byte-identical last-written FX-03 input does not experience repeated
  normalization; byte-different terminal re-copy findings are documented.

### Phase 3 — Targeting and timing proof

**Goal:** Characterize the known foreground-window targeting boundary.

Tasks:

1. Copy from an approved terminal and immediately focus a disallowed app before
   the notification is handled.
2. Keep an approved terminal foregrounded while a background application writes
   FX-01 to the clipboard.
3. Copy from a disallowed foreground application while an approved terminal is
   visible but not foregrounded.
4. Repeat rapid focus transitions at least ten times.
5. Record foreground process, expected source, decision, and false-positive or
   false-negative outcome.
6. If practical, observe `GetClipboardOwner` for the same cases without changing
   product behavior.

Decision gate TG-01:

- **Accept foreground-only targeting** if false positives cannot be reproduced
  in normal use and false negatives are tolerable/documented.
- **Plan an origin-signal refinement** if a background writer is normalized or
  ordinary terminal copies are frequently missed.
- Any refinement must remain behind `IForegroundProcessProvider` or a successor
  targeting interface and must not introduce a keyboard hook.

### Phase 4 — Clipboard ecosystem and resilience proof

**Goal:** Prove the suppression model under intermediaries and contention.

#### 4.1 Windows clipboard history

1. Enable Win+V history.
2. Normalize FX-01, then FX-03 so the normalized FX-03 value is clici's current
   last-written output.
3. Confirm the byte-identical FX-03 self-write notification is suppressed.
4. Record duplicate history entries created by clici's rewrite.
5. With an approved terminal foregrounded, restore the normalized four-space
   FX-03 history entry and confirm it remains unchanged because it matches
   clici's last-written output byte-for-byte.
6. With a disallowed application foregrounded, restore that same normalized
   entry and confirm it remains unchanged because foreground targeting rejects
   it before suppression is evaluated.
7. With an approved terminal foregrounded, restore the original six-space
   FX-03 history entry and confirm the byte-different value normalizes once to
   four spaces.
8. With a disallowed application foregrounded, restore the original six-space
   entry and confirm it remains at six spaces.

#### 4.2 Rapid changes and contention

1. Perform rapid successive copies alternating FX-01, FX-04, and FX-03.
2. Create a bounded clipboard-contention case with a proof-only helper.
3. Confirm clici remains responsive and fails safely after four attempts.
4. Confirm no stale pending marker suppresses unrelated content.

#### 4.3 Clipboard managers and cloud clipboard

1. If installed, repeat FX-01 and FX-03 with the clipboard manager enabled.
2. Repeat with cloud clipboard enabled where available.
3. Record notification reordering, restoration, duplicate entries, and any
   repeated normalization.

#### 4.4 RDP or remote clipboard

1. Run the approved-source copy on one side of an RDP/remote clipboard session.
2. Paste on both local and remote sides.
3. Repeat FX-01, FX-03, and FX-04.
4. Record foreground process ownership and sequence/order anomalies.

Blocking rule:

- Repeated normalization when the clipboard input is byte-for-byte identical
  to clici's current last-written FX-03 output is a release blocker.
- A visually identical terminal re-copy or restored entry whose bytes differ
  from the current last-written value may normalize again; record this as a
  documented limitation, not a release blocker.
- Clipboard exceptions, ordering changes, or unavailable remote infrastructure
  are not blockers if clici leaves content unchanged and the limitation is
  documented.

Exit criteria:

- POC-05 passes under local clipboard history and rapid-change conditions.
- No available intermediary repeatedly normalizes byte-identical last-written
  content; byte-different restoration findings are documented.
- Any unavailable clipboard-manager, cloud, or RDP environment is recorded as
  blocked with its exact prerequisite.

### Phase 5 — Non-text clipboard-format decision

**Goal:** Resolve POC-08 explicitly without expanding scope by default.

Tasks:

1. Copy FX-10 from at least one rich-text source.
2. Record available clipboard formats before normalization.
3. Trigger an eligible normalization.
4. Record formats after normalization.
5. Confirm plain Unicode text remains correct.

Decision gate CF-01:

- **Defer preservation for local POC** if format loss is understood, clearly
  documented, and acceptable for CLI-agent text.
- **Implement preservation before distribution** if common terminal or editor
  workflows lose required formats or behavior.

If implementation is required:

- change only the `IClipboardService` adapter boundary;
- add format-preservation integration tests;
- never deserialize or log arbitrary clipboard payloads; and
- rerun Phases 2 through 4 after the change.

### Phase 6 — Findings, corrective batches, and regression

For each failed case:

1. Add the failure to the ledger before editing code.
2. Classify it as product behavior, platform limitation, test-environment issue,
   or implementation defect.
3. Identify the owning requirement and smallest affected component.
4. Write or update an automated regression test where practical.
5. Implement one coherent corrective batch.
6. Run targeted tests and repeat the failed manual case.
7. Inspect the complete diff.
8. Commit using a conventional commit message.
9. Continue the matrix from the interrupted case.

Do not combine unrelated fixes discovered in different proof cases.

### Phase 7 — Proof report and release recommendation

Create `docs/v0.1-proof-report.md` with:

- tested commit and environment;
- AC-001 through AC-020 result;
- POC-01 through POC-09 status;
- source/destination support matrix;
- observed foreground process names;
- manual cases passed, failed, blocked, or not applicable;
- Win+V, clipboard manager, cloud clipboard, and RDP findings;
- non-text format decision;
- accepted limitations;
- unresolved blockers;
- recommendation: continue local evaluation, fix and repeat, or prepare a
  distribution slice.

Then:

1. Update the specification POC status column from evidence.
2. Update README support and limitation statements.
3. Rerun restore, formatting verification, Release build, and all tests.
4. Review the full repository diff and privacy scan.
5. Commit and push the proof report and deliberate changes.
6. Create a version tag only if the report recommends a stable POC milestone.

## 10. Risks and stop conditions

| Risk | Response |
|---|---|
| Byte-identical last-written content is normalized again | Stop the matrix, preserve evidence, fix before continuing |
| Visually identical terminal re-copy changes clipboard bytes and normalizes again | Record the documented limitation; this alone is not a release blocker |
| Two listeners are active | Stop; single-instance proof has failed |
| Malformed config is overwritten | Stop; restore backup and fix persistence guard |
| Clipboard content appears in diagnostics | Stop, preserve no log copy, fix privacy breach |
| Background writers are routinely normalized | Invoke TG-01; do not broaden process defaults blindly |
| RDP or clipboard manager reorders notifications | Verify content-authoritative suppression before deciding support |
| Rich formats are lost | Invoke CF-01; do not add broad format handling without evidence |
| Required test environment is unavailable | Mark blocked with exact missing prerequisite; continue independent cases |
