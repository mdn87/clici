# clici v0.1 Resilience and Coexistence Report

- **Run date:** 2026-08-06
- **Platform:** Windows 11, x64, .NET 10.0.110
- **Clipboard history:** enabled
- **Clipboard intermediary:** PowerToys Advanced Paste enabled and running
- **Evidence:** synthetic markers only; unrelated history content was never output

## Outcome

The initial happy path worked, but adversarial testing reproduced four product
defects. All four were corrected and verified in the installed tray build:

1. very large items caused excessive memory use and multi-second UI-thread work;
2. WinForms added a hidden retry loop beyond clici's intended contention budget;
3. an older large normalization could overwrite a newer clipboard item; and
4. rich formats were lost and the first history opt-out policy removed the item
   from Win+V entirely.

The hardened build is running from `%LOCALAPPDATA%\Programs\clici\clici.exe`.

## Evidence

| Case | Before | Hardened result |
|---|---|---|
| 1,000 lines / 48,000 chars | Normalized | Normalized in 166 ms |
| 10,000 lines / 480,000 chars | Normalized | Normalized in 247 ms |
| 100,000 lines / 4.8M chars | ~963 ms and elevated memory | Skipped unchanged under the 2M-char ceiling |
| 250,000 lines / 12M chars | ~2.9 s; ~325 MB working set | Skipped by default; controlled raised-limit test remained alive |
| 50 immediate writes | Writer contention and long hidden retries | 50/50 writes completed; final item normalized in 161 ms |
| Old/new sequence race | Older normalization overwrote the newer item | Newer item preserved; stale-write guard observed |
| Forced crash and restart | Unproven | Two forced crashes recovered; one process and one listener remained |
| Second launch | Unproven | Exited within the bound with code 0 |
| HTML/RTF | Lost | Both retained with normalized Unicode text |
| Windows history, opt-out policy | Source delta 0; normalized delta 0 | Replaced with explicit inclusion policy |
| Windows history, inclusion policy | N/A | Source delta 0; normalized delta 1 |
| PowerToys Advanced Paste | Running during tests | Remained alive and responsive throughout |

The final Win+V query returned 17 total history items. For the unique synthetic
test marker it observed exactly one new normalized item and no source duplicate.
It compared only exact synthetic strings and did not emit unrelated history text.

## Implemented safeguards

- `maximumTextCharacters` defaults to 2,000,000 and is validated.
- Oversized text is skipped before hashing or normalization.
- The clipboard sequence is rechecked immediately before replacement.
- Stale writes are skipped without arming self-write suppression.
- Reads retry if the sequence changes while formats are captured.
- Clipboard writes use one explicit four-attempt, 20 ms retry policy.
- HTML, RTF, and CSV strings are retained.
- Normalized writes carry DWORD `1` for `CanIncludeInClipboardHistory` and
  `CanUploadToCloudClipboard`.
- Abandoned mutexes are reacquired after a crash.
- Focused Windows app tests cover size limits, stale writes, self-write
  suppression, format/history metadata, concurrent instances, and abandoned
  mutexes.

Microsoft documents that clipboard listeners receive
`WM_CLIPBOARDUPDATE` whenever clipboard content changes, which explains why a
normalization is a second observable write:
[AddClipboardFormatListener](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-addclipboardformatlistener).
Microsoft also documents the history/cloud control formats and their DWORD
semantics:
[Clipboard formats](https://learn.microsoft.com/windows/win32/dataxchg/clipboard-formats).
Windows history supports up to 25 entries and 4 MB per item:
[Using the clipboard](https://support.microsoft.com/windows/using-the-clipboard-30375039-ce71-9fe4-5b30-21b7aab6b13f).

## Remaining risks

- Foreground-process attribution can still misclassify a background writer or
  a fast focus change.
- Third-party clipboard managers may record both source and rewrite even though
  Windows history coalesced the tested pair.
- Rich destinations may prefer preserved HTML/RTF and therefore retain the
  source margin; plain-text destinations receive normalized text.
- Source-specific formats other than HTML, RTF, and CSV may be lost.
- Raising the size ceiling reintroduces the measured memory and latency cost.
- A clipboard change in the tiny interval between the final sequence check and
  the WinForms write remains theoretically possible; eliminating that interval
  would require a lower-level atomic writer.
- RDP clipboard behavior remains blocked until an approved remote session is
  available.
- Synthetic entries created during this proof remain in Win+V history until
  Windows evicts them or the user clears them.
