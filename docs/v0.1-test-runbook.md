# clici v0.1 Windows Test Runbook

- **Audience:** operator performing the local Windows proof
- **Specification:** [Introductory Slice and Windows Platform Proof of Concept](introductory-slice-spec.md)
- **Execution plan:** [v0.1 Implementation-Completion and Windows Proof Plan](v0.1-implementation-and-proof-plan.md)
- **Estimated time:** 60–90 minutes locally, plus any RDP session
- **Required platform:** interactive Windows 10 or later session

## 1. Purpose

Use this runbook to produce repeatable evidence for the 19-step Windows proof
matrix without recording personal clipboard data.

The run is successful when:

- the Release build and all automated tests pass;
- POC-01 through POC-07 and POC-09 have evidence;
- every manual matrix row is pass, fail, blocked, or not applicable;
- byte-identical last-written text is never normalized again;
- only one clici process and listener can remain active;
- configuration and clipboard failures are safe and bounded; and
- any limitations have an explicit decision in the proof report.

This runbook does not authorize a keyboard hook, installer, configuration GUI,
network service, or unrelated product change.

## 2. Safety and approval gate

Before starting, explicitly approve these temporary local changes:

1. clici may create or modify `%LOCALAPPDATA%\clici`;
2. the test will overwrite the Windows clipboard with checked-in synthetic
   fixtures;
3. Win+V will retain synthetic test entries until Windows removes them or the
   operator clears history; and
4. screenshots may capture the tray, menus, and synthetic fixtures only.

Do not continue without that approval.

Rules for the entire run:

- Save any clipboard item you care about somewhere appropriate before testing.
  Do not copy it into the proof directory.
- Use only FX-01 through FX-10.
- Never paste clipboard text, fragments, hashes, or screenshots containing
  personal data into the ledger.
- Record `MatchesInput`, `MatchesExpected`, or `UnexpectedContent`, not the
  clipboard value.
- Keep raw evidence under the ignored `artifacts/v0.1-proof/` directory.
- Exit clici through its tray menu whenever clean shutdown is under test.
- Do not use Task Manager or `Stop-Process` as evidence of clean shutdown.

Immediately stop the run if:

- byte-identical last-written FX-03 loses another two spaces;
- two listener windows or two persistent clici processes are observed;
- a malformed configuration file changes after a run-only toggle;
- diagnostics contain clipboard text;
- clici hangs or blocks clipboard access indefinitely; or
- a test would require personal or production data.

## 4. Prepare the run

Open PowerShell at the repository root. Confirm no clici process is running. If
one is running, exit it from the tray first.

```powershell
$repo = (Resolve-Path .).Path
$runId = Get-Date -Format 'yyyyMMdd-HHmmss'
$runRoot = Join-Path $repo "artifacts\v0.1-proof\$runId"
$configRoot = Join-Path $env:LOCALAPPDATA 'clici'
$configBackup = Join-Path $runRoot 'config-backup'

New-Item -ItemType Directory -Force -Path `
  $runRoot, `
  (Join-Path $runRoot 'diagnostics'), `
  (Join-Path $runRoot 'screenshots'), `
  (Join-Path $runRoot 'notes') | Out-Null

Copy-Item `
  -LiteralPath '.\tools\proof\run-ledger-template.md' `
  -Destination (Join-Path $runRoot 'run-ledger.md')

$hadConfigRoot = Test-Path -LiteralPath $configRoot
if ($hadConfigRoot) {
    Copy-Item -LiteralPath $configRoot -Destination $configBackup -Recurse
}

[pscustomobject]@{
    RunId = $runId
    Repository = $repo
    ConfigRoot = $configRoot
    HadConfigRoot = $hadConfigRoot
    Started = (Get-Date).ToString('O')
} |
    ConvertTo-Json |
    Set-Content -LiteralPath (Join-Path $runRoot 'run-state.json')
```

The backup remains local and ignored. Do not commit it.

Record the tested commit and environment:

```powershell
git status --short --branch
git rev-parse HEAD
Get-ComputerInfo |
  Select-Object WindowsProductName, WindowsVersion, OsBuildNumber, OsArchitecture
dotnet --info
```

Copy only those environment facts into `environment.md`. Do not use
`Start-Transcript`; it can capture unrelated console or clipboard activity.

## 5. Automated baseline

Run each command from the repository root:

```powershell
dotnet restore clici.sln
dotnet format clici.sln --verify-no-changes --no-restore
dotnet build clici.sln --configuration Release --no-restore
dotnet test clici.sln --configuration Release --no-build
dotnet list src/clici.Core/clici.Core.csproj package
dotnet list src/clici.Core/clici.Core.csproj reference
```

Pass criteria:

- restore succeeds;
- the format check reports no required changes;
- Release build reports zero warnings and zero errors;
- every test passes;
- `clici.Core` has no package or project reference; and
- the working tree contains no generated config or diagnostic log.

Record the totals in ledger row `BASELINE`. Do not continue if build or tests
fail.

## 6. Lifecycle and tray proof

Run:

```powershell
pwsh -NoProfile -File .\tools\proof\Invoke-CliciLifecycleProof.ps1
```

The helper pauses twice. Each time:

1. confirm there is one clici tray icon and no main window;
2. right-click the tray icon;
3. confirm these entries exist:
   - Enabled;
   - Pause normalization;
   - Open configuration file;
   - Open configuration folder;
   - Exit;
4. choose **Exit**; and
5. return to PowerShell and press Enter.

The helper passes only if:

- the primary owns exactly one hidden clipboard-listener window;
- a second process exits within five seconds;
- the second process creates no second listener;
- tray Exit removes the primary listener;
- a new process reacquires the mutex and listener; and
- the final tray Exit leaves zero clici processes and listeners.

Record M01, M16, and M18. Capture tray/menu screenshots only if no unrelated
notifications or clipboard content are visible.

## 7. Configuration and tray controls

The first lifecycle launch should create:

%LOCALAPPDATA%\clici\config.json

and `schemaVersion`, and does not contain the retired `minimumMarginLineRatio`

### 7.1 Enabled persistence

1. Start the Release executable.
2. Clear **Enabled** in the tray.
3. Exit through the tray.
4. Confirm `enabled` is `false` in `config.json`.
5. Restart and confirm the tray item is still clear.
6. Select **Enabled**, exit, and confirm `enabled` is `true`.

Record M09.

### 7.2 Pause is run-only

Calculate the config hash, pause and resume from the tray, then calculate it
again:

```powershell
$configPath = Join-Path $configRoot 'config.json'
$beforePauseHash = (Get-FileHash -Algorithm SHA256 -LiteralPath $configPath).Hash
```

After pause/resume and tray Exit:

```powershell
$afterPauseHash = (Get-FileHash -Algorithm SHA256 -LiteralPath $configPath).Hash
$beforePauseHash -eq $afterPauseHash
```

Pass requires `True`. Record M10.

### 7.3 Open actions

Start clici and select both **Open configuration file** and
**Open configuration folder**. Confirm each opens the expected LocalAppData
path. Record M11, then exit.

### 7.4 Malformed configuration

With clici stopped:

```powershell
$validConfig = Join-Path $runRoot 'notes\valid-config.json'
Copy-Item -LiteralPath $configPath -Destination $validConfig

'{"enabled":' |
  Set-Content -LiteralPath $configPath -NoNewline -Encoding utf8

$malformedBefore = (Get-FileHash -Algorithm SHA256 -LiteralPath $configPath).Hash
```

Start clici. Toggle **Enabled** once, then exit. The toggle must affect only the
running process because the source document did not parse.

```powershell
$malformedAfter = (Get-FileHash -Algorithm SHA256 -LiteralPath $configPath).Hash
$malformedBefore -eq $malformedAfter
```

Pass requires `True`. Preserve the before/after hashes, not file contents, in
M12. Restore the valid synthetic configuration:

```powershell
Copy-Item -LiteralPath $validConfig -Destination $configPath -Force
```

### 8.1 Byte-identical FX-03 suppression

After a successful FX-03 normalization, keep clici running and the approved
terminal foregrounded:

```powershell
pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciFixtureProof.ps1 `
  -Action SetExpected -FixtureId FX-03

Start-Sleep -Milliseconds 250

pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciFixtureProof.ps1 `
  -Action Classify -FixtureId FX-03
```

Pass requires `MatchesExpected`. Any additional margin removal from this
byte-identical value is a release blocker.

To characterize terminal re-copy:

1. pause clici;
2. run `ShowExpected` for FX-03;
3. select and copy the displayed text through the terminal;
4. classify it while still paused; and
5. resume clici.

If the paused re-copy is not `MatchesExpected`, the terminal changed the bytes.
A later normalization of that byte-different value is a documented limitation,
not a self-write suppression failure.

### 8.2 Paused and disabled behavior

While paused, copy FX-01 from an approved terminal. Classification must be
`MatchesInput`. Resume and repeat; it must be `MatchesExpected`.

Disable clici and repeat the same pair of checks. Re-enable it before
continuing.

### 9.2 Exclusion precedence

Add the observed approved process name to `excludedProcessNames`, leave it in

Pass requires `MatchesInput`. Remove the exclusion and restart before

### 9.3 Background writer with terminal foreground

From a separate PowerShell prompt, schedule a hidden synthetic writer:

```powershell
$fixtureHelper = (Resolve-Path '.\tools\proof\Invoke-CliciFixtureProof.ps1').Path

Start-Process pwsh -WindowStyle Hidden -ArgumentList @(
  '-Sta',
  '-NoProfile',
  '-File',
  $fixtureHelper,
  '-Action',
  'SetInput',
  '-FixtureId',
  'FX-01',
  '-DelayMilliseconds',
  '2000'
)
```

Immediately keep an approved terminal foregrounded for at least three seconds,
then classify FX-01.

This deliberately probes the known timing gap: `MatchesExpected` means the
background writer was attributed to the foreground terminal. Record the
observation in M07 and invoke decision gate TG-01; do not silently call this a
pass.

### 9.4 Fast focus changes

## 10. Clipboard resilience

Run the automated resilience helper before the manual cases:

```powershell
pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciResilienceProof.ps1 `
  -Action Scale

pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciResilienceProof.ps1 `
  -Action Rapid

pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciResilienceProof.ps1 `
  -Action MultiFormat

pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciResilienceProof.ps1 `
  -Action History

pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciResilienceProof.ps1 `
  -Action CrashRestart
```

With the default two-million-character ceiling:

- 1,000 and 10,000 generated lines normalize;
- 100,000 generated lines report `SkippedOverLimit` and remain byte-identical;
- the rapid test recovers to a normalized final item after bounded contention;
- the crash/restart test leaves one live process, one listener owned by that
  process, and a secondary launch exit code of zero;
- clici remains alive and responsive after every case.

> **Harness update required (v0.1.1).** `Invoke-CliciResilienceProof.ps1`
> predates the privacy/format safety changes. Its `RichFormat` action still
> expects HTML/RTF to survive a rewrite, but automatic mode now **skips** items
> carrying rich formats, and its `History` action still expects one-valued
> history/cloud flags, but clici now **preserves** source policy and forces
> neither. Update those two actions (assert skip-on-rich and
> preserve-not-force) before re-running History/RichFormat.

For the sequence race only, temporarily set `maximumTextCharacters` to
`20000000`, keep diagnostic logging enabled, restart clici, and run:

```powershell
pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciResilienceProof.ps1 `
  -Action SequenceRace `
  -ExpectedMaximumCharacters 20000000 `
  -RaceDelays 120
```

Pass requires `NewerItemPreserved`, `StaleGuardObserved=True`, and a live clici
process. Restore `maximumTextCharacters` to `2000000` and restart immediately
after this case.

### 10.1 Rapid changes

With an approved terminal foregrounded, run:

```powershell
$sequence = @('FX-01', 'FX-04', 'FX-03') * 5
foreach ($fixtureId in $sequence) {
    pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciFixtureProof.ps1 `
      -Action SetInput -FixtureId $fixtureId
    Start-Sleep -Milliseconds 50
}
```

After processing settles, classify FX-03 and perform one ordinary FX-01 copy.
Pass requires:

- clici remains responsive;
- the final FX-03 has at most one normalization;
- the following FX-01 normalizes normally; and
- no unrelated value is suppressed.

Record M13.

### 10.2 Contention

With an approved terminal foregrounded:

```powershell
pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciFixtureProof.ps1 `
  -Action SetInputAndHold `
  -FixtureId FX-01 `
  -HoldMilliseconds 500
```

The helper sets the fixture and immediately reacquires the clipboard. Because
this is a scheduling race, repeat the case up to three times if clici processes
the value before the helper acquires the lock. A reproduced contention case
should classify as `MatchesInput`: clici exhausted its four-attempt budget
without rewriting. It must remain responsive. If contention cannot be
reproduced after three attempts, record M17 as blocked by timing rather than
calling the product behavior a failure.

Then set FX-01 normally:

```powershell
pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciFixtureProof.ps1 `
  -Action SetInput -FixtureId FX-01

Start-Sleep -Milliseconds 250

pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciFixtureProof.ps1 `
  -Action Classify -FixtureId FX-01
```

Pass requires `MatchesExpected`, proving recovery after contention. Record M17.

## 11. Clipboard history and intermediaries

### 11.1 Win+V

Confirm clipboard history is enabled:

```powershell
(Get-ItemProperty `
  'HKCU:\Software\Microsoft\Clipboard' `
  -ErrorAction SilentlyContinue).EnableClipboardHistory
```

Do not enable account/cloud synchronization solely for this test.

1. Normalize FX-01, then FX-03 (the four-space base collapses to column zero).
2. Open Win+V and record whether each rewrite creates a duplicate entry. clici
   does not react to its own write (private marker, hash fallback), so a
   runaway duplicate loop must not occur.
3. Prepare an approved terminal as the paste target and restore the normalized
   FX-03 entry. It must remain byte-identical, and a second normalization must
   be a no-op (`NotEligible`).
4. Prepare Notepad as the paste target and restore the same normalized entry.
   It must remain unchanged.

For every restoration, record the source process name from clici diagnostics.
Win+V may cause `ShellExperienceHost` or another shell process to be observed;
judge the targeting result from the resolved source (clipboard owner first,
foreground fallback).

Record M14 and decision DEC-02. Confirm the privacy invariant directly: because
FX fixtures are copied by clici's own test harness with no privacy formats set,
the normalized clipboard item must contain **neither**
`CanIncludeInClipboardHistory` **nor** `CanUploadToCloudClipboard` — clici
preserves source policy and never forces either. To check preservation, copy a
source that explicitly sets one of those DWORDs and confirm the value survives
the rewrite unchanged.

### 11.2 PowerToys or another clipboard manager

If PowerToys Advanced Paste, Ditto, CopyQ, or another intermediary is installed,

restoration, notification reordering, and byte-identical self-write behavior.

If no intermediary is installed, record `Not applicable`; do not install one
for the proof.

### 11.3 RDP or remote clipboard

Run this section only with an already approved remote destination. Do not infer
or choose a remote host.

Repeat FX-01, FX-03, and FX-04 across the remote clipboard in both directions.
Record foreground process names and ordering anomalies. If no approved remote

## 12. Rich-format behavior

Create a synthetic rich-text source while clici is paused:

```powershell
$richFile = Join-Path $runRoot 'notes\FX-10.html'
@'
<!doctype html>
<meta charset="utf-8">
<pre><strong>  [FX-10] First line</strong>
  Second line
    Nested line</pre>
'@ | Set-Content -LiteralPath $richFile -Encoding utf8

Start-Process $richFile
```

Select and copy the rendered block. Record format names only:

```powershell
pwsh -Sta -NoProfile -File .\tools\proof\Invoke-CliciFixtureProof.ps1 `
  -Action InventoryFormats
```

Resume clici, copy the same rendered block again, wait 250 ms, and inventory
formats again. In automatic mode clici must **skip** this item because it
carries HTML/RTF: the clipboard is unchanged (rich formats and the original
plain text both intact, no clici self-write marker present), and diagnostics
record `skipped-rich-or-nontext-content`.

Do not record format payloads. Record M19 and decide CF-01:

- accept plain-text-only automatic mode (rich items skipped) for this release; or
- prioritize consistent rich-format (HTML/RTF) normalization as future work if a
  common workflow needs rich items normalized rather than skipped.
