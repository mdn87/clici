# clici v0.1 functional proof ledger

**Status: in progress (run `20261016-214754`).** Nineteen manual cases (M01–M19)
are defined below; rows without a result have not been run yet. This file records that gap
honestly rather than leaving it invisible.

This ledger lives in `docs/` deliberately. It previously sat under
`artifacts/v0.1-proof/<run-id>/run-ledger.md`, and `artifacts/` is gitignored —
so its emptiness could not be seen in a clone. Evidence that a clone cannot see
is not evidence. Bulky artifacts (logs, JSON, captures) still belong under
`artifacts/` and should be referenced from here by path.

## What "run" requires

These are **manual** cases. They need an operator at a Windows keyboard doing
real clipboard work across terminals, editors, Win+V history, and RDP — they
cannot be closed by an agent alone, and several cannot be closed by an agent at
all. Note also that agent-session HKCU reads on 4070pc are unreliable (see the
hazard section of `docs/installer-test-runbook.md`); any case resting on a
registry read must be observed from an interactive shell.

Related and already closed: the **installer** runbook
(`docs/installer-test-runbook.md`) is a separate sequence and is verified
through step 13. These nineteen are the functional clipboard cases, not those.

## Recording rules

- Do not paste clipboard text or fragments into this ledger. Refer to synthetic
  fixtures by ID only (`tools/proof/fixtures.json`).
- Label machine-asserted results separately from operator-observed ones. A y/n
  from a human is not the same class of evidence as a log line.
- Record the build under test as a full informational version
  (e.g. `0.1.0+01f99de8`), not just "0.1.0" — several results this project has
  produced were against builds that differed from what shipped.

Resolved by skipping ownerless writes (TG-01 resolution; event `skipped-ownerless-source`). Verified 2026-10-17 on installed build `0.1.0+dd7dd89b` with Windows Terminal foreground (`agent-scripts/verify-ownerless.ps1`, `diagnostics/verify-ownerless-dd7dd89.txt`): an ownerless FX-01 write stayed `MatchesInput` (`skipped-ownerless-source`); a pwsh-owned FX-01 write was still `Normalized`; a Notepad copy followed by Notepad exit stayed `MatchesInput` (two `skipped-rich-or-nontext-content`, then `skipped-ownerless-source`). A conhost `cmd` copy is owned by `cmd/ConsoleWindowClass` (`diagnostics/conhost-watch.log`), so legacy-console copies keep a source.
